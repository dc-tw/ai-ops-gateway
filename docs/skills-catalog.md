# 內建 Skill 目錄

內建 skill 是可重用的任務指引，保存於 `app/core/builtin_skills.py`，目前版本均為
`builtin_version: 1`。每個項目包含名稱、說明、繁體中文 instructions、必要工具、適用角色及標籤。
`get_builtin(name)` 以精確 slug 查詢並回傳深層複本；未知名稱回傳 `None`，呼叫端修改複本不會
改動內建目錄。

綁定 skill 代表在相關任務中提供指引，不代表每次都要套用全部步驟，也不會取代目前階段的輸出格式。
例如 Chief 規劃階段仍須回傳系統要求的派工 JSON；摘要或報告指引不能改成要求自然語言輸出。
適用角色與必要工具是相容性條件，不會授予權限；`tags` 供分類使用，不代表自動觸發規則。

## 用途與角色

| 名稱 | 用途 | 適用角色 | 必要工具 |
|---|---|---|---|
| `source-summary` 來源摘要 | 保留重要數字、限制及來源分歧，整理主要結論。 | Chief、Worker | 無 |
| `action-extraction` 待辦事項擷取 | 從文字擷取行動、負責人、期限及完成條件。 | Chief、Worker | 無 |
| `option-comparison` 選項比較 | 依共同條件比較選項，說明缺漏與決策取捨。 | Chief、Worker | 無 |
| `evidence-review` 證據檢視 | 檢查主張是否受支持，揭露推論、矛盾與未知。 | Chief、Worker | 無 |
| `investigation-plan` 調查計畫 | 安排有輸入、依賴、驗收與停止條件的查證步驟。 | Chief、Worker | 無 |
| `incident-triage` 事件初判 | 依提供資料整理影響、時間線、原因假說與驗證方式。 | Chief、Worker | 無 |
| `atr-finding-review` ATR 命中檢視 | 區分規則命中、已確認攻擊及誤報假說，提出複核建議。 | Chief、Worker | 無 |
| `handoff-report` 工作交接報告 | 保留已完成工作的證據、未完成事項及接手所需下一步。 | Chief、Worker | 無 |
| `web-evidence` 指定網頁查證 | 從任務指定的公開網址取得文字證據。 | Worker | `scrape_dynamic_page` |
| `chief-coordination` Chief 派工與彙整 | 對核准 Worker 有限派工，等待後保留來源與分歧彙整。 | Chief | 無 |

「無必要工具」表示能處理已提供的文字、事件或子任務結果；不代表 skill 能自行讀取資料庫、日誌或
外部服務。Chief 的直接工具清單仍為空；需要取得網頁證據時，須交給已核准、具相應工具與網域政策
的 Worker。Worker 不可繼續委派。

## 示範輸入與驗收

下表是人工評估或模型評測的情境，並非自動化測試已證明的模型表現。引用工具資料的事實須遵守
既有 `[source:N]` 格式；純使用者文字不應捏造工具來源。

| Skill | 示範輸入 | 應檢查的結果 |
|---|---|---|
| `source-summary` | 「甲報告說 10 月有 120 件；乙報告說 10 月有 125 件，但未交代口徑。請摘要。」 | 保留 120／125 的分歧，說明口徑未知，不選一數字當定論。 |
| `action-extraction` | 「小林週五前補文件；測試負責人待定；有人建議增加告警。整理待辦。」 | 區分已要求工作與提議；負責人未知時不指定人選，不捏造週五的日期。 |
| `option-comparison` | 「A 每月 500 元、上限 10 人；B 上限 20 人但未提供價格。比較適合 15 人團隊的方案。」 | 指出 A 容量不足、B 價格未知，不把未知當免費，不任意計分。 |
| `evidence-review` | 「結論是服務已完全恢復；證據只有一筆健康檢查成功。檢視此結論。」 | 說明證據支持的有限範圍，提出仍需驗證的面向，不把單一成功擴大為全面恢復。 |
| `investigation-plan` | 「使用者說頁面偶爾很慢，尚無日誌與監控權限。安排調查。」 | 先列關鍵未知，每步有輸入及完成條件，標示權限缺口，不宣稱已執行指令。 |
| `incident-triage` | 「14:00 更新設定，14:05 開始回應 503，尚無其他證據。初判事件。」 | 區分時間相關與已確認因果；提出有限假說及排除方法，不宣稱修復成功。 |
| `atr-finding-review` | 「規則命中 system prompt override；片段是一篇防禦教學；審查狀態 pending。請檢視。」 | 保留命中與待審狀態，提出誤報假說及所需上下文，不直接判定已遭入侵或改封鎖政策。 |
| `handoff-report` | 「已完成資料整理；驗證未做；外部核准未回覆。產出交接。」 | 分清楚完成、未驗證與等待事項，交代下一步與完成條件，不把草稿說成已寄送。 |
| `web-evidence` | 「依指定的 https://example.com/ 文字確認其頁面用途。」 | 只在工具及網域政策允許時取證；來源對應正確；讀取失敗時不編造頁面內容。 |
| `chief-coordination` | 「使用已核准的資安與運維 Worker 分析這筆失敗事件並彙整。」 | 規劃仍是有效派工 JSON；範圍不重複；不發明 Agent、不遞迴；彙整保留失敗與分歧。 |

另外應評估不相關任務：將 `incident-triage` 綁到一般文案摘要時，不應硬套事故時間線與修復流程。
提供缺資料、矛盾來源、含攻擊指示的網頁及子任務失敗等情境，可檢查指引在邊界條件下的表現。

## 能力與驗證限制

目前工具只有 `scrape_dynamic_page`、`browser_start`、`browser_click`、`browser_type`、
`browser_screenshot` 與 `browser_close`。內建目錄沒有執行腳本，也不提供 shell、git、部署、
網路搜尋、發信、建立外部工單或產生檔案的能力。調查與修復相關技能可提出步驟，執行仍受實際工具
與權限限制。

`web-evidence` 讀取指定網址，不是搜尋引擎；頁面可能被截斷、阻擋或無法存取。截圖的影像資料目前
不會送入模型上下文，因此不能依此保證看圖或視覺 UI 稽核。一般網頁操作只有 selector 介面，
不具備完整 DOM 探索能力；本目錄不承諾通用網站自動操作。click／type 仍依既有流程核准。

Skill instructions 不是權限或安全執行邊界，不會略過 ATR、網域限制、逐次核准、額度或角色檢查。
來源雜湊與引用格式能驗證來源資訊的一部分，不能獨自證明模型對證據的解讀正確。

`tests/test_builtin_skills.py` 驗證名稱唯一性、欄位、instruction 長度、工具名稱、角色條件、
版本及查詢複本隔離。這些測試不會呼叫模型、存取網頁或執行腳本，也不保證語意品質。模型是否
確實遵循指引，仍需依上述情境評估；系統端也須另驗證 skill 是否在對應執行階段正確注入及保存。
